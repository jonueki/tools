If the user named a file or function, read it first. If no target is specified, ask for one.

1. **What it does** — the purpose in one sentence
2. **Why it exists** — the problem it solves or the role it plays in the system
3. **Key decisions / quirks** — anything non-obvious: invariants, sign conventions, ordering requirements, gotchas
4. **How it connects** — what calls it, what it calls, what data it owns
5. **What to watch out for** — common mistakes or footguns when modifying it

Guidelines:
- Plain language first, code references second
- Under 300 words unless the subject is genuinely complex
