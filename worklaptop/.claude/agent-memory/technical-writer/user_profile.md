Senior/staff-level engineer at Remitly. Side projects in TypeScript/Next.js/SQLite.

**Documentation preferences:**
- Sparse is better. Don't document what the code already says clearly.
- Comments only when the WHY is non-obvious — hidden constraints, subtle invariants, workarounds.
- No multi-paragraph docstrings. One short line max.
- READMEs should be practical: quick start first, details after.
- No trailing summaries after writing — direct delivery only.

**Project style:** CLAUDE.md files are kept lean with durable rules. STATUS.md tracks current state. README.md is user-facing setup.

**Stack context:** TypeScript, Next.js, SQLite. Audience for docs is themselves returning to the code cold, or a new contributor.
